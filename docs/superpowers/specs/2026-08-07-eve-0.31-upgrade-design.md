# eve 0.19.0 → 0.31.3 upgrade — approved design

**Date:** 2026-08-07
**Branch:** `chore/upgrade-eve`
**Status:** approved, pending implementation

---

## 1. Context

`packages/compiler/versions.json` pins `eve@0.19.0` (2026-07-02). npm latest is
`0.31.3` (published 2026-08-07) — twelve minor releases in five weeks. This is a
migration, not a patch bump.

Two structural facts shape everything below:

1. `computeAgentHash` folds `deps.versions` (the whole of `versions.json`) into
   the content hash. Bumping eve therefore **re-hashes every agent version** —
   new artifact, new platform-JWT audience, new world database `ag_v_<hash12>`.
   Nothing upgrades in place.
2. `agent_versions.eve_version` is `notNull`, so the control plane *can*
   distinguish protocols per version. We deliberately choose not to (see §3).

The `beta` dist-tag on eve (`0.6.0-beta.20`) is stale and sorts *below* latest.
Never resolve eve by tag; the exact-pin rule already covers this.

## 2. Scope

**In:** the forced session-API migration, the version matrix, and the
high-value features that serve surfaces we already ship — turn cancellation,
stable stream event ids, bounded catch-up reads, the Anthropic prompt-cache
fix, explicit runtime limits, and the HITL `kind` discriminator.

**Out (tracked as follow-ups):** mounted extensions, `eve/evals`, remote
agent-to-agent delegation (`defineRemoteAgent` with runtime-resolved URL +
`forwardPrincipal`), the durable `sleep` tool, subagent token attribution, and
per-agent spend limits in the agent editor.

## 3. Decision: republish-to-migrate

The control plane speaks the 0.31 protocol **only**. Already-published agent
versions keep serving their 0.19.0 artifacts until their agent is republished,
at which point they rebuild onto the new hash.

Rejected alternatives: a dual-protocol client keyed on `eve_version` (costs a
compatibility layer, its authz tests, and a later deprecation pass), and a
forced backfill rebuild at deploy time (rebuilds every artifact and provisions
a fresh world DB per agent at once).

Consequence to accept: a dispatch to a stale published version fails loudly
until the agent is republished.

## 5. Forced migration: session API v2

0.31.0 replaced continuation-token session APIs with fixed, ID-addressed
handles. Required changes:

- **`apps/control-plane/src/runtime/worker-client.ts`** — `EveSessionCreated`
  drops `continuationToken`. `continueEveSession` addresses by `sessionId`
  alone. `EveContinueRequest` becomes a discriminated union: 0.31 made
  `message` and `inputResponses` mutually exclusive (`send` vs `respond`). Add
  `cancel`, `clear`, `compact`, `reset`.
- **`apps/control-plane/src/runs/store.ts`** — delete
  `updateSessionContinuation` and the continuation-token lookup.
- **Database** — `agent_sessions.continuation_token` is already nullable. Stop
  writing it; leave the column and its partial index in place. **No migration**
  — this honors the additive-migrations rule. Record as a residual for a later
  cleanup pass.
- **`apps/control-plane/src/runtime/errors.ts`** — the busy 409 becomes
  `code: "session_not_active"`. This is a *semantic* widening, not a rename:
  0.19's `session_busy` meant "a turn is running"; 0.31's `session_not_active`
  also covers terminal and reset sessions. `dispatch.ts` has logic that evicts
  a stuck claim rather than bricking a Slack thread forever — re-read that path
  against the new meaning rather than swapping the string.
- **`packages/shared/src/api.ts`**, `apps/web` client, e2e fixtures follow.

New route surface (verified against the 0.31.3 bundled docs):

```
POST /eve/v1/session                    create + first message
POST /eve/v1/session/:sessionId         follow-up (send XOR respond)
POST /eve/v1/session/:sessionId/cancel  cancel the in-flight turn
POST /eve/v1/session/:sessionId/clear   clear model history, keep session
POST /eve/v1/session/:sessionId/compact compact context
POST /eve/v1/session/:sessionId/reset   retire the session
GET  /eve/v1/session/:sessionId/stream  NDJSON events
```

Accepted async work returns `202`. Unknown or terminal session ids return `409`
with `code: "session_not_active"`, readable as `ClientError.code`.

## 6. Adopted features

### 6.1 Plumbing (no UI)

1. **Stable `evt_`-prefixed ULID `meta.id`** on every stream event (0.28.0).
   The tailer dedupes on a stable id instead of index arithmetic. The
   documented pre-0.28 caveat (events persisted earlier carry `meta.at` but no
   `meta.id`) does not apply to us — every session lands on a fresh hash.
2. **Bounded catch-up reads** — `follow: false` plus the
   `x-eve-stream-tail-index` response header (0.27.7) for the tailer's resume
   path, and `streamReconnectPolicy: { reconnect: false }` (0.27.2) so our
   tailer keeps owning cursor recovery instead of contending with eve's
   internal reconnect (added in 0.26.0).
3. **Anthropic prompt-cache fix** (0.22.2) — free with the bump. The final
   cache breakpoint sat one message early, capping effective hit rate near 50%
   on tool loops. No code change; called out because it is a real cost win.
4. **HITL `kind` discriminator** (0.28.0) — plumb into `EveInputRequest` in
   `packages/shared` so `ApprovalCard` routes tool approvals, questions, and
   session-limit decisions explicitly instead of inferring from tool names.

### 6.2 Explicit runtime limits

eve now applies a **default 40,000,000 input-token budget** per root session
and a **30-day `sessionTimeoutMs`**, whether or not we configure them. Crossing
the token budget pauses the session and raises a deterministic Approve/Stop
continuation prompt; at the timeout, eve emits `session.completed` and the next
message starts a fresh session.

We set both **explicitly** in the `defineAgent` codegen at values matching
today's effective behavior, rather than inheriting new defaults silently. This
is a platform constant — per-agent spend limits in the editor are out of scope.

Note for the chat surface: interactive sessions get the HITL prompt (answerable
through the existing `ApprovalCard` path once `kind` is plumbed); task-mode runs
skip it and fail with `SESSION_TOKEN_LIMIT_REACHED`.

### 6.3 User-facing (apps/web)

5. **Stop button** — a control-plane route fronting
   `POST /eve/v1/session/:id/cancel`, an E1 capsule control in agent chat, and
   stream-reducer handling for the `turn.cancelled` → `session.waiting` pair.
   eve is explicit that cancellation is *a user decision, never an error* —
   the run must not land in `failed`.

   **Amended 2026-08-07 (post-implementation).** This originally read "in agent
   chat *and run detail*". There is no run-detail surface in `apps/web` and
   never was: the route table is agents / chat / context / workflows /
   settings, and the one place a run is dispatched outside chat — the workflow
   builder's `TestRunPopover` — links "View in Chat" rather than rendering the
   run itself. Every run in the product is observed in chat, so chat is the
   complete Stop surface, not half of one. Building a run-detail route to
   satisfy the original wording would have added a product surface duplicating
   chat, well outside an eve upgrade. Recorded here rather than silently
   dropped.
6. **Context controls** — `clear` / `compact` / `reset` as chat menu actions.
   `reset` is destructive (the retired id can never accept another message), so
   it requires a confirm step and mints a new session row.

Both follow the E1 design system: existing primitives in `src/components/ui`,
capsule controls, 150–200 ms ease-out, `focus-visible`, designed
empty/loading/error states, `prefers-reduced-motion` respected.

## 7. Verification

Ordered, because the first gate can invalidate everything after it:

1. **Spike suites** — the upgrade gate, and the only place the OpenRouter 3.0.0
   swap and world-postgres alignment are proven empirically.
2. **`COMPILER_VERSION` bump** + `UPDATE_GOLDEN=1` golden-digest regeneration
   (emitted bytes change). `UPDATE_GOLDEN=1` refuses to run without the bump.
3. `bun run typecheck` · `bun test` · DB-gated integration · phase-1 acceptance
   · phase-3 acceptance · Playwright E2E · prod-compose smoke.

Test-lane hygiene from prior sessions: compose projects must not reuse the
harness project names, and infra-bound lanes run serially rather than
concurrently.
